# Kirby 6 with ComposerKit

This project follows the directory structure of the official
[Kirby ComposerKit](https://github.com/getkirby/composerkit) and uses
Kirby `6.0.0-alpha.3`.

## Requirements

- PHP 8.3, 8.4, or 8.5
- Composer
- Laravel Herd (recommended)
- Node.js and npm

## Installation

Install the PHP dependencies from the project directory:

```bash
composer install
```

Install the frontend dependencies:

```bash
npm install
```

## Frontend assets with Vite

Frontend assets are bundled with Vite through
[`arnoson/kirby-vite`](https://github.com/arnoson/kirby-vite) and
`vite-plugin-kirby`. The entries are `src/css/app.css` and `src/js/app.js`.
Tailwind CSS and legacy browser builds are not configured yet.

Link or park the project in [Laravel Herd](https://herd.laravel.com) with
`public/` as the document root, so Kirby is served at
[https://kirby-vite-tailwind.test](https://kirby-vite-tailwind.test). Create
the local `.env` and adjust `VITE_SITE_URL` if your domain differs:

```bash
cp .env.example .env
```

Then start Vite:

```bash
npm run dev
```

Vite opens `VITE_SITE_URL` in the browser. While it runs, editing
`src/css/app.css` updates the page without a reload, and changes to templates,
snippets, or content reload the page. Run only one `npm run dev` at a time.
The local `.env` is ignored by Git.

Create the production build in `public/assets/build/`:

```bash
npm run build
```

`vite-plugin-kirby` generates `site/config/vite.config.php` and uses a `.dev`
file while the development server is running. Both files are ignored by Git.

Build artifacts are not tracked by Git. Before deploying, run `composer install`
and `npm run build` so that `site/plugins/kirby-vite/`,
`public/assets/build/`, and `site/config/vite.config.php` exist on the server.
Do not deploy a `.dev` file, otherwise Kirby tries to load assets from the
development server.

## Environment configuration

Create the local environment configuration from the tracked example:

```bash
cp site/config/env.example.php site/config/env.php
```

Replace the placeholder values for `content.salt` and `cookie.key` with two
different random values. You can generate each value with:

```bash
openssl rand -hex 32
```

Kirby automatically loads `env.php` after the shared `config.php`, so local
values override the shared configuration. The local `env.php` is ignored by
Git and must not be committed.

## Initial content

Content is not included in Git. Create the initial site, home page, and error
page from the project directory after cloning:

```bash
mkdir -p data/storage/content/home data/storage/content/error
printf 'Title: My Kirby Site\n' > data/storage/content/site.txt
printf 'Title: Home\n' > data/storage/content/home/home.txt
printf 'Title: Error\n' > data/storage/content/error/error.txt
```

Replace the example titles with the titles for your project. Keep
`data/storage/content/` writable so Kirby can save changes from the Panel.

ComposerKit uses `public/` as its public document root.

## Directory structure

```text
data/       Content and runtime data generated by Kirby
public/     Public document root containing index.php, media, and built assets
site/       Blueprints, configuration, snippets, and templates
src/        Frontend source files bundled by Vite
vendor/     PHP dependencies installed by Composer
```

`public/index.php` loads the Composer autoloader and configures the separate
paths for content, accounts, cache, logs, and sessions.
